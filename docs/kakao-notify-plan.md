# 매주 리더십 인사이트 알림 받기 — 카카오톡 정기 발송 기획안

> 작성 2026-09-12 · 상태: 기획(미착수)
> 목표: 사이트 하단 '구독하기'를 **"매주 리더십 인사이트 알림 받기"**로 바꾸고,
> 회원가입 없이 신청한 사람에게 **본인이 고른 요일·시간에, 아직 받지 않은 편을 무작위로 골라, 본인 카카오톡으로** 자동 발송한다.

## 1. 왜 '나에게 보내기'인가 — 두 경로 비교

| | A. 알림톡 (비즈메시지) | **B. 카카오 로그인 + 나에게 보내기** |
|---|---|---|
| 신청 시 필요한 것 | 전화번호 + 수신 동의 | 카카오 동의 1탭 (`talk_message`) |
| 우리 사이트 회원가입 | 불필요 | 불필요 |
| 도착 위치 | 우리 **채널** 이름으로 채팅방 | 사용자의 **'나와의 채팅'** |
| 사전 심사 | 템플릿 심사 2~3영업일, **정보성만 허용**(광고성 반려). 콘텐츠 뉴스레터는 회색지대 | 없음(기본 템플릿 즉시 사용) |
| 비용 | 건당 과금(대행사 단가) + 채널 운영 | **0원** (카카오 API 무료) |
| 인프라 | 채널 + 대행사(솔라피·NHN Cloud 등) 연동 | 워커 하나 |
| 한도 | 대행사 계약 범위 | 수신자당 100건/일, 앱 30,000건/일 — 주 1회엔 여유 |
| 유지 리스크 | 템플릿 변경마다 재심사 | 토큰 2개월 만료 → **매주 발송이 곧 갱신**이라 활성 구독자는 문제없음. 2개월 이상 일시정지한 사람만 재동의 |
| 브랜드 | 채널명·프로필 노출 | 발신자가 '나' — 첫 메시지에서 고정(핀) 안내 필요 |

**결정:** 1단계는 B. 2단계에서 규모·브랜딩 필요 시 A를 추가 채널로 붙인다(구독자가 채널 선택).

> 확인 사항: `talk_message` 동의항목은 앱 설정에서 '사용 권한 신청'이 붙을 수 있다. 필요 시 **비즈앱 전환(사업자등록번호 등록)**으로 해결 — NFN 사업자 정보로 가능.

## 2. 사용자 흐름

### 2.1 신청 (사이트 하단, 기존 구독 섹션 교체)

```
[매주 리더십 인사이트 알림 받기]
리더는 시간이 없지, 통찰이 필요 없는 건 아니니까.
원하는 요일·시간에, 아직 읽지 않은 편을 한 편씩 보내드려요.

( 카카오톡으로 받기 ● 추천 )   ( 이메일로 받기 )
```

- **카카오톡으로 받기** 클릭 → `https://notify.projectleadership.cc/kakao/start`
- 카카오 동의 화면: 요청 항목은 `talk_message` 하나 (프로필·이메일 요청 안 함)
- 콜백 → **설정 페이지**(워커가 렌더, 사이트와 같은 디자인 토큰):

```
언제 받을까요?
요일   [월] [화] [수] [목] [금] [토] [일]      ← 복수 선택 가능(기본: 월)
시간   [ 08:00 ▾ ]                            ← 07:00~22:00, 30분 단위
어떤 편을 받을까요?
[전체 ●] [전략] [사람] [판단] [책임] [성장] [성찰] [역사]   ← 주제 필터(선택)
순서   ( 무작위 ● )  ( 최신 편부터 )
□ 위 시간에 카카오톡 '나와의 채팅'으로 인사이트를 받는 데 동의합니다. 언제든 그만 받을 수 있어요.
[ 알림 시작하기 ]
```

- 저장 즉시 **확인 메시지 1건** 발송: "설정이 끝났어요 🦉 매주 월요일 08:00에 한 편씩 보내드릴게요. 이 채팅방을 상단에 고정해 두세요. · 설정 변경 · 그만 받기"
- **이메일로 받기**는 기존 Google Apps Script 폼 유지(2단계에서 같은 저장소로 통합).

### 2.2 받기 (매주)

카카오 기본 템플릿 `feed` 사용:

```
[이미지: assets/og/vol-42.jpg]
Vol. 42 · 부끄러우면 숨긴다
사람에게는 변명이 붙고 기계에는 사실이 나온다. 리더가 받는 보고는 이미 걸러져 있다.
#사람 · 7분
[ 지금 읽기 → ]          ← https://projectleadership.cc/insight-vol-42.html?utm_source=kakao&utm_medium=notify
설정 변경 · 그만 받기    ← 서명된 관리 링크(로그인 불필요)
```

### 2.3 관리 (로그인 없이)

- 모든 메시지 하단 링크 = `/manage?t=<서명 토큰>` (구독자 id + HMAC). 열면 요일·시간·주제 변경, 일시정지, 해지.
- 해지 즉시 레코드 삭제(토큰 포함). 카카오 쪽에서 '연결 끊기'를 해도 다음 발송 실패 시 자동 해지.

## 3. 시스템 구성

```
projectleadership.cc (GitHub Pages, 정적)
  ├─ index.html  ── "카카오톡으로 받기" 버튼 → notify.projectleadership.cc/kakao/start
  ├─ data/volumes.json ── 워커가 매 발송 때 읽는 콘텐츠 목록 (신규 편 자동 편입)
  └─ assets/og/vol-NN.jpg ── 메시지 이미지

notify.projectleadership.cc (Cloudflare Worker)
  ├─ GET  /kakao/start      → 카카오 인가 URL로 리다이렉트 (state 서명)
  ├─ GET  /kakao/callback   → code→token 교환, 구독자 생성, 설정 페이지로
  ├─ GET/POST /settings     → 요일·시간·주제·순서 저장, 확인 메시지 발송
  ├─ GET/POST /manage?t=    → 변경·일시정지·해지
  ├─ CRON */5 * * * *       → 발송 루프
  └─ D1 (SQLite)            → subscribers, sends
```

### 3.1 데이터 (D1)

```sql
subscribers(
  id TEXT PK,                 -- 랜덤 id
  kakao_uid TEXT UNIQUE,      -- 카카오 회원번호
  refresh_token_enc TEXT,     -- AES-GCM 암호화 (키는 Workers Secret)
  refresh_exp INTEGER,        -- 만료 시각
  days TEXT,                  -- '1,3'  (0=일 … 6=토)
  slot TEXT,                  -- '08:00'
  tz TEXT DEFAULT 'Asia/Seoul',
  cats TEXT,                  -- '' 또는 '전략,사람'
  mode TEXT DEFAULT 'random', -- random | latest
  status TEXT DEFAULT 'active', -- active | paused | unsubscribed
  fail_count INTEGER DEFAULT 0,
  sent_vols TEXT DEFAULT '',  -- '42,17,08'
  created_at, updated_at
)
sends(id, subscriber_id, vol, sent_at, ok, error)
```

### 3.2 발송 루프 (5분마다)

1. `now`를 Asia/Seoul로 변환 → `dow`, `HH:MM`(30분 내림).
2. `status='active' AND days LIKE %dow% AND slot=HH:MM AND (마지막 발송이 오늘이 아님)` 조회.
3. 구독자마다:
   - 리프레시 토큰으로 액세스 토큰 발급. 새 리프레시 토큰이 오면 교체(만료 1개월 이내면 카카오가 함께 내려줌).
   - `volumes.json` 최신본 로드 → 후보 = 전체 − `sent_vols` − (cats 필터 밖). 
   - `mode=random`이면 무작위 1편, `latest`면 후보 중 최신 1편.
   - 후보가 없으면 "42편을 모두 받으셨어요. 다음 주부터 2회차를 시작할까요?" 메시지 + `sent_vols` 초기화 링크.
   - `POST /v2/api/talk/memo/default/send` (feed 템플릿).
   - 성공: `sent_vols`에 추가, `sends` 기록, `fail_count=0`.
   - 실패: `invalid_grant`/`-401`(연결 끊김) → `unsubscribed`; 그 외 `fail_count++`, 3회면 `paused`.
4. 한 구독자 = 주 1~7건이므로 카카오 한도(수신자당 100건/일)와 무관. 앱 전체 30,000건/일 → 구독자 수만 명까지 무리 없음.

### 3.3 새 편 발행과의 연결

- `new_volume.py`가 `data/volumes.json`에 편을 추가하면 워커는 다음 실행부터 자동으로 후보에 넣는다. 별도 배포 없음.
- 선택: 발행 직후 '최신 편부터' 모드 구독자에게 즉시 발송하는 웹훅(`POST /publish`)을 `new_volume.py` 끝에 붙일 수 있다(2단계).

## 4. 카카오 설정 체크리스트 (0단계)

1. developers.kakao.com → 앱 생성 "Project Leadership Insight"
2. 플랫폼 > Web: `https://projectleadership.cc`, `https://notify.projectleadership.cc`
3. 카카오 로그인 활성화 → Redirect URI: `https://notify.projectleadership.cc/kakao/callback`
4. 동의항목 > **카카오톡 메시지 전송(`talk_message`)** = 선택 동의. 권한 신청이 요구되면 **비즈앱 전환**(사업자등록번호)
5. 앱 키: REST API 키 · Client Secret(사용 ON) → Workers Secret에 저장
6. 테스트 계정으로 동의→발송 1회 검증

## 5. 정책·개인정보

- **수집 최소화:** 카카오 회원번호, 암호화 토큰, 요일·시간·주제. 이름·전화·이메일 요청 안 함.
- **동의:** 설정 페이지 체크박스(수신 동의 + 처리방침 링크). 메시지마다 해지 링크.
- **시간 제한:** 선택지를 07:00~22:00으로 고정해 야간 발송 자체를 배제.
- **처리방침 추가 문구:** 목적(신청한 인사이트 발송), 항목, 보유기간(해지 시 즉시 삭제), 제3자 제공 없음, 처리 위탁(Cloudflare).
- **카카오 정책 부합:** '나에게 보내기'는 사용자가 직접 설정한 본인 수신용 메시지이며 언제든 해지 가능 — 스팸·광고 전송이 아님을 첫 메시지와 설정 화면에 명시.
- **토큰 보안:** 리프레시 토큰은 AES-GCM으로 암호화 저장, 키는 Workers Secret. 로그에 토큰 미기록.

## 6. 단계별 계획

| 단계 | 내용 | 산출물 | 공수 |
|---|---|---|---|
| **0** | 카카오 앱 설정, `notify` 서브도메인(CNAME → Workers) | 앱 키, 도메인 | 반나절 |
| **1** | 워커(start/callback/settings/manage/cron), D1 스키마, 사이트 하단 섹션 교체, 확인 메시지, 관리 링크 | 동작하는 카톡 알림 | 2~3일 |
| **2** | 이메일 구독을 같은 D1로 통합(요일·시간 동일 UX), 발송 통계(utm), 발행 웹훅, 관리자 화면(구독자 수·실패), 알림톡 채널 추가 검토 | 운영 대시보드 | 1주 |

### 1단계 세부 작업
- [ ] `wrangler` 프로젝트 + D1 생성, 스키마 마이그레이션
- [ ] `/kakao/start` `/kakao/callback` (state 서명, code→token, uid 조회)
- [ ] `/settings` 페이지 (사이트 토큰·폰트 재사용, 다크모드 대응)
- [ ] 발송 모듈: 토큰 갱신 → 후보 선택 → feed 템플릿 전송 → 기록
- [ ] `/manage?t=` (변경·정지·해지) + HMAC 토큰
- [ ] Cron `*/5 * * * *` 핸들러, KST 변환, 중복 발송 방지(하루 1회 잠금)
- [ ] `index.html` 구독 섹션 교체(카톡/이메일 2버튼) + 처리방침 문구
- [ ] 테스트: 동의→설정→확인 메시지→다음 슬롯 발송→관리 링크→해지→재동의

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| '나와의 채팅'을 안 보는 사용자 | 첫 메시지에서 채팅방 상단 고정 안내. 2단계에서 알림톡 채널 옵션 |
| 2개월 이상 일시정지 → 토큰 만료 | 정지 45일째 "곧 연결이 만료돼요" 메시지 + 재동의 링크 |
| 카카오 연결 끊기 | 발송 실패 코드로 감지 → 자동 해지, 재신청 가능 |
| GitHub Pages는 서버가 없음 | 동적 부분 전부 워커. 사이트는 링크만 |
| 정적 파일 캐시로 최신 `volumes.json` 지연 | 워커가 `?cb=timestamp`로 읽거나 GitHub raw 사용 |
| 워커 무료 한도 | 하루 요청 10만·CPU 10ms/요청 — 구독자 수천 명까지 무료 |

## 8. 대안 요약 (선택하지 않은 이유)

- **Google Apps Script + 시트** (지금 이메일 구독에 쓰는 것): 새 인프라 없이 가능하나, 시간 트리거 지연(최대 ±15분)과 OAuth 콜백 처리가 불편. 정확한 시각 발송이 요구사항이라 제외. 급하면 MVP로는 가능.
- **알림톡 단독:** 전화번호 수집·심사·과금이 따라오고 콘텐츠 뉴스레터는 정보성 심사 통과가 불확실. 2단계 옵션으로만.
- **카카오 채널 자동응답/오픈빌더:** 사용자가 먼저 말을 걸어야 해 정기 푸시에 부적합.
